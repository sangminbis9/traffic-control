# 2026-10-09 reward search snapshot

현재 60입력/8행동 DQN의 보상 후보 6개를 각각 50,000 step 학습한 결과입니다.
학습 seed는 22 하나이며, 150,000-step 탐색률 일정을 유지했습니다.

잠정 추천은 **queue=1.0, waiting=0.3, max_waiting=0.5, switching=0.5**입니다.
기본 보상으로 동일하게 50,000 step 학습한 모델과 새 교통 seed 20개로 비교했습니다.

| 최종 평가 지표 | 기본 보상 | 후보 4 | 고정 신호 |
|---|---:|---:|---:|
| 평균 대기시간 (초) | 19.033 | 18.087 | 22.765 |
| 회차별 최대 대기시간의 평균 (초) | 79.575 | 72.525 | 88.025 |
| 평균 대기열 (대) | 14.874 | 14.061 | 17.199 |
| 처리량 (대/회차) | 193.55 | 196.05 | 192.05 |

기본 보상 대비 평균 대기는 4.97% 감소하고 처리량은 1.29% 증가했습니다.
20회 중 12회 대기가 개선됐습니다. 단일 학습 seed의 탐색 결과로,
통계적 유의성이나 전역 최적값을 입증하지 않습니다. 고정 heavy 시나리오의
추가 2회 진단에서는 평균 대기가 기본 보상보다 1.56% 늘고 처리량이 2.91% 줄었습니다.

## 선택 과정과 평가 자료

1. `comparison.csv`: seed 4001~4008로 6개 후보를 비교했습니다.
2. `locked_selection.json`, `recommendation.json`: 최초 1위 후보 6은
   seed 5001~5010 검증에서 평균 대기가 기본값보다 1.58% 늘어 탈락했습니다.
3. 후보 4를 후속 탐색 대상으로 고정한 뒤, 처음 사용하는 seed 7001~7020으로
   다시 확인했습니다. 5001~5010은 후보 4의 선택 자료이며 최종 시험 자료가 아닙니다.
4. 최종 결과는 `final_recommendation.json`과
   `followup_confirmation/comparison.csv`입니다. 고정 시나리오 추가 진단은
   `stress_candidate4/comparison.csv`에 있습니다.

## 모델과 재현 기록

- [추천 설정](recommended_reward_config.json)의 `model_path`는 저장소 루트 기준입니다.
- [추천 모델](experiment_4/final.zip)과 다른 5개 후보의 `final.zip`을 보존했습니다.
- 모델 SHA-256, 설정, 학습/평가 수요 해시, 개별 평가 CSV를 함께 저장했습니다.
- 실제 Python/패키지 버전은 `runtime_packages.json`, SUMO 버전은 각 후보 metadata에 있습니다.
- [상세 보고서](final-report-ko.txt)와 [비교 그림](final_comparison.png)을 함께 볼 수 있습니다.
- `analysis_sources/`는 당시 `.tmp/`에서 실행한 후속 평가·보고서 스크립트의 원본 보관본입니다.
  경로를 포함하므로 이 보관 위치에서 그대로 실행하는 범용 CLI는 아닙니다.
- 원본 provenance와 보고서에는 당시 로컬 절대 경로가 남아 있습니다.
  파일을 찾을 때는 이 디렉터리의 상대 경로와 모델 해시를 사용하세요.

Replay buffer, 중복 중간 checkpoint, 생성된 SUMO 파일은 이 snapshot에 포함하지 않습니다.
따라서 수요 해시와 평가 증거는 보존하지만 중간 학습 상태의 완전한 재개용 archive는 아닙니다.
기존 기본 모델과 기본 보상 설정은 변경하지 않았습니다. 급제동 경고가 있었으므로
충돌·텔레포트 0을 포괄적인 안전성 입증으로 해석해서는 안 됩니다.
